# AIMathTutor Changelog — Version 4.0.14

## Fixed

- Admin forms and the admin password dialog show why a save was rejected, such as a username that is already taken,
  instead of "Unexpected error occurred"
- `make password` hashes the whole password when it contains a space, not just its first word, and no longer
  passes the password on the Maven command line
- In the admin area, a password longer than 72 characters is refused with a message that names the 72-character
  limit, instead of one about 100 characters or about bytes
- Releases publish multi-platform images straight from the build, so a release can no longer replace them with a
  single-platform or stale local image

## Security

- Updated DOMPurify from 3.4.15 to 3.4.16 to address event handlers left active on content
  removed during in-place sanitization (GHSA-p98j-92pf-mc4p)
- Updated source-map-js, used by the frontend build, from 1.2.1 to 1.2.2 to address a denial of service through
  crafted source maps (GHSA-68fv-2mgg-jv7q)
- Saving a user no longer makes them an administrator when their selected rank was deleted while the user form was
  open; the save is rejected instead
- A production build started with the `dev` or `test` profile no longer drops and recreates the database tables,
  deleting all data; it refuses to start instead. Remove that profile setting (e.g. `QUARKUS_PROFILE`) from the
  deployment. A deployment that already started this way needs its data restored from a backup
- Users who may manage users or ranks can no longer give themselves or others more permissions than their own rank
  has: they can't assign a higher rank or add permissions their rank lacks to any rank, and they can't change, reset
  the password of or delete a user whose rank is above their own, or change or delete such a rank
- The last active administrator can no longer be deleted, banned, deactivated or demoted, including by removing
  permissions from their rank, so nobody is locked out of the admin area. Since nobody can grant a permission their
  own rank lacks, only an active user whose rank has every permission counts as an administrator. If you removed a
  permission from the Admin rank before upgrading, nobody counts, so nothing is protected: restore the Admin rank
  with the README's "Recovering administrator access" steps, which now restore every permission
- A banned or deactivated user can no longer use their rank's permissions, such as editing users or content, from
  a page that was already open
- A production build whose Hibernate schema management is set to anything but `validate` or `none`, for example
  `QUARKUS_HIBERNATE_ORM_SCHEMA_MANAGEMENT_STRATEGY` or the deprecated `QUARKUS_HIBERNATE_ORM_DATABASE_GENERATION` set to
  `drop-and-create` or `update`, refuses to start; `drop-and-create` used to delete all data. Remove the setting, or
  set it to `validate`. Never re-run `init.sql` on a database that holds data: it drops every table first
- Changing a password, whether the user or an administrator does it, ends the account's other sessions: they lose
  the account's permissions at once and are signed out at their next page change; the session that made the change
  stays signed in
- A user banned, deactivated or deleted could stay signed in for up to 30 more seconds if they changed pages at the
  moment of the change; they are now signed out on their next page change
- Changing one's own password allows at most 5 attempts per 15 minutes in each signed-in session, so a stolen session
  can't guess the current password, and can't block the owner's own password change or their logins
- An open page stays tied to its own account: after a user is deleted or renamed, it can no longer act as a later
  account given the same username, and renaming a user no longer signs them out
