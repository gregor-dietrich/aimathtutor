# AIMathTutor Changelog — Version 5.0.0

## Added

- Database schema is created and upgraded automatically on startup.
- Four designs (Vellum, Power-Up, Vibranium and Chalkboard) and a colour mode
  (Light, Dark or Follow system), chosen per user under Settings → Appearance
  and saved to the account. Existing and new accounts start with Vellum
  following the system setting. The fonts of the designs are served by the
  application itself.

## Changed

- Quarkus platform version updated from 3.40.1 to 3.40.1.1
- Vaadin version updated from 25.3.1 to 25.3.3
- New installations no longer contain demo lessons, exercises, sessions or
  teacher/student accounts.
- New installations no longer contain an `admin` account with the password
  `admin`. The first admin account is created on the first start from the
  `APP_BOOTSTRAP_ADMIN_USERNAME` (default `admin`) and
  `APP_BOOTSTRAP_ADMIN_PASSWORD` settings; without a password, the application
  refuses to start.
- Success, warning and error colours are easier to read, especially in dark
  mode.
- Warning messages are now shown in yellow.
- The "Reset Filters", "Enter Custom Problem" and "Show Published Only" buttons
  use the default button style.
- Badges have a new, rounder look.
- The colour-mode button in the top bar now saves the choice to the account, and
  is hidden when signed out.

## Fixed

- Password changes show the specific rejection reason and allow correcting the
  input, including the documented 72-character maximum.
- AI providers fail promptly on permanent HTTP client errors, such as an invalid
  API key, instead of retrying the same rejected request. The tutor then gives
  no feedback instead of generic fallback hints, and the chat says that it is
  not available.
- Permission checks and rank display no longer load every member of the rank.
- Production startup reports recovery instructions while no active administrator
  exists, for example after deactivating former demo accounts removed the last
  one.
- Docker images apply their required JVM options and accept operator options
  through `JDK_JAVA_OPTIONS`.
- Production deployment uses the tracked `deploy/compose.yml`, with matching
  PostgreSQL pins and complete optional Ollama instructions.
- OpenAI Organization ID instructions point to Admin Settings, where the value is
  stored and used.
- In dark mode, the page background below the content and the math workspace
  (canvas, on-screen keyboard and help) are now dark too.
- "Follow system" now follows a change of the operating system's setting while a
  page is open. The math workspace switches from dark to light only on the
  next page load.
- The colour mode no longer carries over to the next sign-in in the same
  browser.
- The comments button in the exercise administration is labelled "Show
  Comments", which is what it does.
- The comment form on an exercise sits on one card, with space between the text
  box and the "Post Comment" button.
- Exercise hints are split only at line breaks, as the editor describes, so a
  hint may contain a semicolon or a vertical bar. Hints that were separated by
  one of those on a single line now show as one hint; put each on its own line.
  The former demo exercises of an upgraded installation show their hints one by
  one instead of as a single bracketed list, unless they were edited.
- Repeated failed sign-ins now lock out for longer each time, up to one hour.
  Failures are remembered until a successful sign-in, or until an hour after the
  lockout ends; before, the count started over after a minute, so guessing could
  continue at several attempts a minute.
- Behind a reverse proxy, the sign-in limits use the client address the proxy
  adds to `X-Forwarded-For` instead of the first entry, which the client can set
  itself. Entries that are not IP addresses are no longer used.
- Failed sign-ins with many different usernames no longer lift an existing
  lockout.

## Upgrade Notes

- Upgrade to the latest 4.0.x first. Its database is adopted automatically
  without manual SQL. Databases from older releases must be brought to the 4.0.x
  schema before upgrading.
- The database no longer needs an initialization script. Remove the
  `docker-entrypoint-initdb.d` mount from existing Docker Compose files: if the
  database volume is ever recreated while it is still mounted, the old script
  creates the former demo accounts with their publicly known passwords.
- If the `admin` account still has the password `admin`, the application refuses
  to start until `APP_BOOTSTRAP_ADMIN_PASSWORD` is set, and then replaces that
  password once. Accounts with any other password are not affected. Remove the
  setting after the first successful start.
- The former demo accounts `teacher`, `student1` and `student2` are deactivated
  on startup while they still accept their publicly known passwords. Set new
  passwords before reactivating them.
- The repository's `docker-compose.yml` now builds the app image from the
  checkout and is for development. Deploy with `deploy/compose.yml`, which runs
  the published image: download it as described in the Quickstart, but into the
  directory of the existing deployment, beside its `.env`, replacing the old
  `docker-compose.yml`. Compose names the database and encryption key volumes
  after that directory, so a new directory starts with an empty database and a
  new key. If the old stack ran from a checkout, use a new directory and set
  `COMPOSE_PROJECT_NAME` in its `.env` to the checkout directory's name. Then
  run `docker compose pull` and `docker compose up -d --remove-orphans`: the
  pull replaces a cached `latest` image, and `--remove-orphans` stops services
  the new file no longer defines, such as a pgAdmin published on all
  interfaces.
- The images never read `JAVA_OPTS` or `JAVA_OPTS_APPEND`. Move such options to
  `JDK_JAVA_OPTIONS`.
- Behind more than one reverse proxy, list the address of every proxy in
  `app.security.trusted-proxy-ips`, not only the one the application connects
  from; otherwise all sign-ins count against the outer proxy's address, and a few
  failures lock everyone out for a while. Entries must be IP addresses; hostnames
  and address ranges are ignored, with a warning in the log.
